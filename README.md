# Translatable Tree

Демонстрационный проект на Qt: дерево данных с поддержкой перевода интерфейса на русский и английский языки «на лету», с возможностью подмены источника переводов без изменения кода модели.

## Задание

> В стандартных библиотеках Qt есть класс для отображения данных - `QTreeView`.
> Этот класс не поддерживает встроенные функции перевода на другой язык в Qt (`tr`).
> Необходимо разработать класс, который будет отображать дерево данных с возможностью перевода на английский язык и обратно.
> Визуально класс не обязательно должен быть идентичен `QTreeView`, но должна быть сохранена топология дерева.

## Что сделано

- Реализована кастомная модель `TranslatableItemModel` (наследник `QStandardItemModel`), работающая с любым `QTreeView` и поддерживающая перевод данных.
- Топология дерева **сохраняется полностью**: иерархия узлов, вложенность, три столбца (`Параметр`, `Переданные значения`, `Значения`).
- Ключ перевода хранится отдельно от текста - в пользовательской роли `KeyRole` (`Qt::UserRole + 1`). Это позволяет менять язык без перезагрузки данных.
- Перевод заголовков столбцов также поддержан.
- Реализованы **два независимых источника переводов** за общим интерфейсом
  `ITranslationProvider`:
  - `JsonTranslationProvider` - читает словари из JSON-файлов;
  - `QtTranslationProvider` - использует штатный `QTranslator` + `.qm`.
- Источник переводов и язык можно переключать **на лету** кнопками в UI.
- Данные дерева загружаются из JSON через отдельный класс `TreeLoader`, не смешиваясь с логикой перевода.

## Почему не `tr()` и не стандартный `QTreeView`

`QTreeView` - это **представление**, оно не хранит данные и, соответственно, не может их переводить. `tr()` работает на этапе компиляции исходников и не подходит для данных, которые приходят извне.

Поэтому перевод вынесен на уровень **модели** и **провайдера переводов**:
- модель знает, что у ячейки есть ключ (`KeyRole`), но не знает, откуда брать перевод;
- провайдер знает, откуда брать перевод, но не знает про модель;
- `MainWindow` связывает их и инициирует обновление.

Такое разделение позволяет:
- добавить новый язык без правки модели;
- добавить новый источник переводов без правки UI;

## Структура проекта

```

translatabletree.pro        # сборка через qmake
main.cpp                    # точка входа

ui/
    mainwindow.h
    mainwindow.cpp          # окно, кнопки, связывание модели и провайдеров

model/
    translatableitemmodel.h/.cpp   # модель дерева с переводом
    treeloader.h/.cpp              # загрузка дерева из JSON
    itemroles.h                    # KeyRole

translation/
    itranslationprovider.h         # интерфейс источника переводов
    jsontranslationprovider.h/.cpp # реализация на JSON
    qttranslationprovider.h/.cpp   # реализация на QTranslator + .qm

resources/
    resources.qrc
    data/
        data.json           # структура дерева
        ru.json             # словарь RU
        en.json             # словарь EN
    translations/
        tree_ru.ts
        tree_en.ts
        tree_ru.qm
        tree_en.qm
```

## Сборка

Требуется Qt 6 (Widgets, LinguistTools) и qmake.

### qmake

```bash
mkdir build-qmake && cd build-qmake
qmake ../translatabletree.pro
make -j$(nproc)
./app
```

`.qm`-файлы подхватываются из ресурсов (`:/translations/...`).

## Как переключать язык и источник

В окне две кнопки:

- **«Переключить на EN / Switch to RU»** - меняет язык (`Lang::Ru и Lang::En`).
- **«Источник: .json / .qm»** - переключает провайдер переводов (`JsonTranslationProvider ↔ QtTranslationProvider`).

Обе кнопки вызывают соответствующие слоты `MainWindow`, которые дергают `TranslatableItemModel::SetLanguage()` / `SetProvider()`.
Модель перебирает ячейки с `KeyRole` и подставляет перевод.

## Что можно улучшить дальше

1. Перенести перевод из `setText()` в `data()`
2. Вынести пути к ресурсам и список языков в конфиг.
3. Добавить `QTest` - тесты на провайдеры и загрузчик.
4. Добавить третий язык и третий источник, чтобы проверить расширяемость.
